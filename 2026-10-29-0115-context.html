🛠️ Deep Diagnoses & Root Cause Fixes

  • Tailscale SSH Self-Connection Trap:

    Linux kernel table local routes packets destined for the machine's own 100.x.y.z IP to loopback (dev lo), bypassing tailscale0. Tailscale SSH only intercepts external packets arriving across WireGuard. Self-connection fails by design; connections must originate from another node.

  • KDE Plasma 6 KRDP Cert Generation Bug:

    The GUI checkbox "Generate certificates automatically" in System Settings leaves file paths empty ("") in ~/.config/krdpserverrc. Fixed by generating a 10-year TLS cert via openssl and explicitly writing file paths via kwriteconfig6.

  • KDE Plasma 6 PAM unix_chkpwd Lockout:

    KDE systemd user units run with NoNewPrivileges=true, preventing unix_chkpwd from reading /etc/shadow and triggering pam_faillock account lockouts. Fixed via systemd drop-in override setting NoNewPrivileges=false.

  • Windows Host vs. WSL2 Mesh Isolation:

    Native Windows apps (mstsc.exe) run on the Windows NT host, not inside WSL2. If Tailscale is only running in WSL2, Windows cannot route 100.x.y.z or resolve *.ts.net. Windows host Tailscale or WSLg connection is required.

📜 Architecture Decisions & Clarified Rules

1. Machine Identity Parameterization (Decision A1 & A2):

  • Endpoints are strictly per-machine (pdf-envy, pdf-asus). Both machines can be online simultaneously without Tailnet collisions.
  • Stored locally in git-ignored local-services/.env (file permissions 0600). Never committed to GitHub.
  • Auto-detects from hostname; interactive confirmation on first setup with strict sanitization (max 10 alphanumeric characters).

2. Zero-Trust SOPS Secret Lifecycle (Decision A4):

  • Each bootstrapped machine adds its SSH public key (~/.ssh/id_ed25519.pub) to .sops.yaml.
  • Decryption is 100% ephemeral in memory during container launch (zero plaintext tokens on disk).
  • Monthly GitHub Actions token rotation re-encrypts the auth key specifically for all authorized machine public keys.

📋 Actionable Resumption Guide: Onboarding the Asus Laptop

When you switch over to the Asus laptop, follow these exact steps to complete cross-device synchronization:

1Pull Latest Code & Run Bootstrap on Asus:

git pull origin main && ./bootstrap.sh --skip-cleanup

The script will auto-detect [asus], confirm the nickname, generate local-services/.env, and register Asus's SSH public key.

2Authorize Asus SSH Key in SOPS:

If Asus does not have a pre-existing decryption key, run from the Asus terminal:

Then, from this envy laptop (which is already authorized):

git pull && sops updatekeys -y secrets/tailscale.enc.yaml && git commit -am "chore(sops): re-encrypt for asus" && git push

3Start Services on Asus:

git pull && jl up-remote && jl up-desktop
