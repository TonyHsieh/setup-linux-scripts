🛠️ Solved Incidents & Session Accomplishments

🔥 Incident 1: Chrome RESULT_CODE_HUNG Freeze During Boss Fights

Root Cause: Milestone 4.16 wired renderer.update() to call sound.setBossHpRatio(boss.hp / boss.maxHp) at 60 Hz, and SoundEngine.setBossHpRatio() unconditionally called Tone.getTransport().bpm.rampTo(targetBpm, 0.2) on every tick — even when boss HP had not changed. In Tone.js 14.8.49, TickParam._events is an unpruned new Timeline(Infinity); stacking overlapping 200ms linear ramps at 60 Hz (and twice in the same audio quantum when fixed-timestep accumulator ran 2+ steps) corrupted getDurationOfTicks(1, nextTickTime) to return <= 0, locking TickSource.forEachTickBetween in an infinite while (nextTickTime < endTime) loop. Headless Vitest missed it because this.Tone is null without Web Audio.

Permanent Fix: Added _lastAppliedBpm and _lastBpmRampEndAt guards in src/audio/soundEngine.ts so Transport.bpm.rampTo only schedules when BPM changes by >= 1.0 and the prior ramp has finished. Synced trackers in applyMusicModeToTone(), added a 60 Hz mock-Tone regression test in src/game/milestone416.test.ts, and verified the fix live in browser playtesting.

📐 Accomplishment 2: Model Gallery Spacing Parity with In-Game Proportions

Issue: src/game/gallery.ts rendered every model at a flat scale = 4.5 and spacingPx = 3.4px (ratio 0.76), ignoring getEntitySpacingMultiplier(kind) (1.42× for non-Recogniser characters) and per-entity in-game spacing / scale ratios (Hero/enemies 1.99, Bosses 1.24, Recogniser 0.90).

Fix: Updated GALLERY_DEFAULT_SPACING to 2.8 (exact in-game BASE_LAYER_SPACING), exported computeGalleryCardSpacing(...), and added per-entry in-game metadata (kind, inGameScale, inGameSpacingMult, galleryScale) so every turntable card renders with exact in-game 3D aspect ratios while preserving live W/S / ↑/↓ tuning. Added unit test in src/game/milestone416.test.ts.

🌡️ Accomplishment 3: Smooth Boot Thermometer (No More 2% Stall → Blink to 100%)

Issue: src/main.ts set progress to 2% and awaited an opaque Promise.all([...]) across all 6 dynamic module imports. In Vite dev mode, ESM network/transform loading took almost all the wall-clock time while the bar sat frozen at 2%, then the ~12 fast canvas bakes zoomed 25% → 100% in ~200ms.

Fix: Replaced the opaque wait in src/main.ts with individually tracked imports across 4% → 55% with real stage labels plus a gentle asymptotic creep timer, mapped bootstrapAssets onto 55% → 96%, and updated loading.ts finish() to hold briefly (160ms) at 100% READY before fading out over 240ms.
