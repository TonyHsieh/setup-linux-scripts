🛠️ Incident Resolution: Devenv Directory Assertion Failure

Symptom: Running direnv allow after scaffolding a flake caused evaluation crash:

error: Failed assertions:
- devenv was not able to determine the current directory.
  See https://devenv.sh/guides/using-with-flakes/ how to use it with flakes.
  • Root Cause Diagnosed: Nix Flakes evaluate in pure mode by default. In pure mode, builtins.getEnv "PWD" returns an empty string "". Cachix devenv's internal top-level.nix module asserts that config.devenv.root != "", triggering an immediate evaluation abort.
  • Universal Template Fix: Updated all 5 templates (python, node, rust, kubernetes, devenv-starter):
    1. In .envrc: Switched to use flake . --impure to pass the host working directory to Nix.
    2. In flake.nix: Added an explicit fallback for devenv.root so pure checks (e.g. nix flake show) also evaluate without crashing.

⚡ Feature: Dual-Condition Dependency Auto-Sync

Goal: Seamless developer experience for Python projects with or without requirements.txt, with zero manual watch_file edits.

  • Graceful Missing-File Handling: If requirements.txt is missing, direnv and devenv load with zero errors and print a friendly best-practice tip encouraging dependency declaration.
  • Pre-Wired watch_file: Because direnv allows watching non-existent files without errors, watch_file requirements.txt is always active. The second the file is created or saved, direnv automatically reloads.
  • Writable Venv & Notebook Compatibility: Enabled languages.python.venv.enable = true; in .devenv/state/venv, pre-seeded pip for notebook !pip install compatibility, and bound stdenv.cc.cc.lib (libstdc++.so.6) + zlib so C++ extensions like SentencePiece link without linker errors.
