🔍 Incident Report: devenv shell Terminal Lockup Resolution

✅ Issue Resolved & Verified Live
The command prompt freezing after running devenv shell in /home/tonyh/_Projects/resume-aligner has been diagnosed, permanently fixed in code, and verified. devenv shell now launches and executes in under 200ms without terminal deadlocks or high CPU usage.
Technical Deep-Dive: Root Cause Analysis

Using GDB to inspect the stuck bash process (PID 10299, spinning at 99.8% CPU), we uncovered an escape sequence recursion loop inside ble.sh (Bash Line Editor):

Component Trigger & Failure Mechanism Permanent Resolution
tmux (allow-passthrough) In tmux 3.3a+, allow-passthrough defaults to off. When ble.sh queried secondary device attributes (DA2 via \e[>c), tmux intercepted the query and replied 84;0;0 (identifying tmux). ble.sh tried querying through tmux via \ePtmux;...\e\, but tmux intercepted and replied again. This repeated 19 times until escape doubling (${ret//$'\e'/$'\e\e'}) created 524,288 sequences (800+ KB), freezing bash. Added set -g allow-passthrough on to home/tmux.nix. Tmux now cleanly forwards passthrough queries to the host terminal.
devenv PTY Proxy Collision devenv shell creates its own nested pseudo-terminal (PTY) proxy. ble.sh was unconditionally executing ble-attach in every interactive bash session, trying to capture line editing inside devenv's child PTY where DCS escapes cannot pass. Added an explicit subshell guard in home/shell.nix:
if [[ $- == *i* && -z "${DEVENV_ROOT:-}" && -z "${IN_NIX_SHELL:-}" && -z "${BLE_SESSION_ID:-}" ]]; then
ble.sh is now skipped inside devenv/nix-shell, providing clean standard GNU Readline inside subshells.
Font Width Probing On startup, ble.sh emitted bursts of private-use characters ([▽][▶][龼][鿄]...) to measure terminal glyph widths. Configured bleopt char_width_mode=emacs in home/shell.nix, eliminating probe glyph bursts and latency.
